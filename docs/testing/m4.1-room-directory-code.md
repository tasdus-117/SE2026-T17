Domain `RoomDirectory` dùng monotonic receipt clock injectable, TTL6s, không tin UTC để expiry; revision cũ không rollback/gia hạn lease. Public listing sort code, tối đa64; cache tối đa256 record gồm tombstone. Remove chỉ tác động RoomInstanceId tương ứng; tombstone trong TTL chặn heartbeat cũ đến sau remove. Đây là cache LAN có giới hạn, không phải durable registry hoặc chống replay vô hạn trên mạng không tin cậy.

## Discovery và admission

- Discovery mặc định **UDP47777**, multicast **239.255.42.99**, multicast loopback bật, TTL mạng1. Socket reuse-address cho nhiều local listeners; broadcast cùng port hỗ trợ LAN. Không dựa vào broadcast chia sẻ port để fan-out localhost.
- Game KCP giữ cổng cấu hình hiện hữu, mặc định7777. Nhiều **host** cùng máy phải dùng game ports riêng; không dùng discovery port làm game port.
- UDP adapter không có worker/background thread: manager Update gọi Tick, budget128 datagram/frame, tối đa1200 bytes/datagram; unknown version/kind, malformed payload và listing sai bị bỏ. Heartbeat2s, query/reply debounce1s. Endpoint lấy IP của sender, không tin địa chỉ tùy ý trong payload.
- Wire discovery `ARD1`: kind query/publish/remove; publish/remove mang instance/revision; listing là giá trị có bounds, không deserialize kiểu tùy peer. Packet trùng revision không làm mới TTL; public/private chỉ là chính sách hiển thị, không phải bí mật hoặc access control.
- Hai instance trùng RoomCode bị resolve DirectoryUnavailable; instance có ID ordinal lớn hơn nhường mã, manager sinh mã mới và publish snapshot lại. Uniqueness chỉ trong cache LAN đã hội tụ, không hứa global uniqueness qua partition.
- Lobby admission message version1 mang expected code/instance khi code-join. Server kiểm trước khi phát ServerConnected/thêm roster; stale room hoặc version sai bị reject, pending admission có timeout5s. Raw-address peers gửi version hiện hành với identity rỗng để giữ entry cũ, vẫn chịu đúng cap/phase/Ready rules.
- **Cần rebuild cùng phiên bản client/server**: LobbySnapshot có code/instance/public và client phải gửi admission. Không coi binary M3 cũ là wire-compatible. `--arena-*` semantics và instrumentation harness cùng-source được giữ; virtual peer test helper đã gửi admission theo wire mới, không bỏ assertion cũ.
- Room-enabled Host/Server được quảng bá; Bootstrap direct/debug room-disabled giữ luồng chẩn đoán hiện hữu. Không biến discovery thành auth/token/reconnect hoặc thay lobby Start bằng UI.
- StopServer/StopHost gửi remove rồi dispose; crash mất heartbeat sẽ hết TTL. OnDestroy dispose idempotent. LAN UDP không có confidentiality/authentication; chỉ phù hợp demo LAN tin cậy, không chứng nhận Internet hoặc secure registry.

## CLI và kiểm tra thủ công

Giữ nguyên `--arena-server`, `--arena-client`, `--arena-host`, `--arena-address`, `--arena-port` và direct Bootstrap semantics. Hai option mới:

```text
--arena-discovery-port 47777
--arena-room-code ABC234
```

Option mới không tự bật role hoặc Hub; parser reject port0 và mã không hợp lệ, normalize code. CLI direct/debug không phải nghiệm thu UI Hub.

1. Dùng build cùng source cho mọi instance; MainMenu/Multiplayer hiện hữu Host Room vẫn hoạt động. TV3 M4.2 nối Hub tới IRoomBrowserPort; không có Hub screen mới trong nhiệm vụ này.
2. Mở browser port, Refresh rồi xem GetDiscoveredPublicRooms; host phải hiện1/4/Lobby/public với code6. Từ client dùng JoinRoomByCode, chờ RoomChanged có2 members; chỉ truyền code, không set networkAddress từ UI.
3. Hai người Ready mới Start; listing đổi InMatch, code join mới bị từ chối. Rời peer trả slot; peer thứ5 vẫn có room-full notice, không ảnh hưởng bốn thành viên hợp lệ.
4. Stop host: listing bị remove, browser không giữ room vô hạn. Thử host mới/code mới, port discovery giống nhau. Nếu hai host cùng máy, cấu hình KCP port khác nhau.
5. Thử code sai/không tồn tại, cancel trong resolution, stale instance sau code reuse; không tạo roster mới hoặc giữ client ở connecting do resolve thất bại.
